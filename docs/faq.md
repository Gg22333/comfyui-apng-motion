# FAQ

**为什么不用 `batch_size`？**
`batch_size=N` 是 N 个互相独立的噪声样本。固定 seed 只保证可复现，不会让它们变成连续帧。

**为什么不像视频那样逐帧生成？**
逐帧 img2img 要 24 次采样，且会累积漂移（黑发漂成青蓝）。插值只需 3–5 次采样，中间帧由数学过渡。

**为什么默认 24 帧？**
24 帧 @10fps = 2.4 秒，够放「起 → 转 → 收」。但帧数是预算不是规格：8 帧做轮播，12 帧做轻动作，24 帧是默认甜点，30 帧给五拍故事，60 帧给网页/Discord 的顺滑预览。都用 `--frames` 改。

**为什么默认 10fps？**
GIF 的延迟单位是 1/100 秒，10fps = 10cs 是精确值；12fps 会变成 8cs（12.5fps）。

**为什么我的图动作很小？**
提高关键帧 `denoise`（UNet 系 0.4 → 0.45；MOSS-Image 0.85 → 0.90），或加大 A/B 提示词差异。不要靠加帧数。

**能让角色走起来吗？**
不能。这条路线没有真实轨迹。走位、转身要用 ControlNet 骨骼序列或视频模型（Wan / LTX）。

**支持 Flux / SD1.5 / 别的模型吗？**
支持。`emit_workflow.py` 只认结构（1 个 denoise=1 的 KSampler + ≥2 个关键帧 + N 插值 + N 解码 + N 路合并 + 3 输出），模型名换成你自己的即可。

**必须用 GPU 吗？**
出图需要。`detect_env` / `doctor` / `emit_workflow` / `check_anim` 都是 CPU 侧工具。

**APNG 和 GIF 哪个好？**
见 [APNG、GIF 与视频转 GIF](formats.md)。结论：聊天用 GIF，网页/透明用 WebP，文档/无损用 APNG。

**为什么 GIF 比 APNG 还小？**
GIF 是 256 色 + LZW，对平涂动漫非常友好；APNG 每帧整帧无损。
