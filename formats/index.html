    APNG、GIF 与「视频转 GIF」：到底差在哪¶

    这一页解释三件事：APNG 为什么适合做表情包、它和「拿视频转 GIF」有什么本质区别、 以及把 APNG 再转成 GIF 时会损失什么。

    1 · APNG 是怎么存的¶

    APNG 不是新格式，是 PNG 的扩展：在普通 PNG 里插入三类块。

    块 作用
    acTL 动画控制：num_frames（帧数）、num_plays（循环次数，0 = 无限）
    fcTL 每帧控制：宽高、偏移、delay_num / delay_den（该帧显示时长）、dispose_op、blend_op
    fdAT 第 2 帧及之后的图像数据

    关键结论（APNG 规范原文）：

    • num_plays = 0 表示无限循环；num_frames 必须等于 fcTL 数量。
    • 帧时长 = delay_num / delay_den 秒；delay_den = 0 按 100 处理，即单位变成 1/100 秒。
    • 第 1 帧就是普通 PNG 的 IDAT，所以不支持 APNG 的解码器会退回显示一张静态 PNG——这是 APNG 最重要的使用逻辑：它天然向后兼容，不会出现"图裂了"。

    这带来两个直接好处：

    1. 一个 .png 文件既是动图又是静态图，聊天软件预览、图床、CDN 都不会报错。
    2. 真彩色 + 真 alpha（RGBA），半透明边缘不糊。

    代价是体积：APNG 的每一帧都是完整 PNG 数据，没有视频那种帧间预测（没有 P/B 帧、没有运动补偿）。 所以同样内容，APNG 通常比 GIF 大，更比 MP4/WebM 大一个量级。

    备注：APNG 规范允许用 x_offset / y_offset + dispose_op 只更新帧的局部区域， 但 Pillow（ComfyUI 的 SaveAnimatedPNG 用的就是它）默认按整帧写，并且会把像素完全相同的相邻帧 合并、把时长累加到上一帧。这就是"排了 24 帧只导出 19 帧"的根因，也是本项目要求同一对 latent 上比例不重复的原因。

    2 · 和「视频转 GIF」的本质区别¶

    两条流水线完全不是一回事：

    视频转 GIF：
  拍摄/生成视频 → H.264/H.265（帧间预测，YUV，有损）
      → 抽帧 → 调色板量化（≤256 色）→ GIF（LZW，1-bit 透明）

本项目（APNG 路线）：
  首帧采样 → 3–5 个关键帧（同一 latent 重绘）
      → LatentInterpolate 插出 24 帧 → VAE 解码（每帧都是完整 RGBA）
      → APNG / WebP / GIF 三路独立编码
    维度 视频转 GIF 本项目
    运动来源 真实采样，有运动模糊与物理轨迹 关键帧之间的数学插值，没有真实轨迹
    能演什么 走位、转身、镜头运动、复杂交互 表情、呼吸、轻微头部动作；大动作要换 ControlNet / 视频模型
    画质 受视频码率与量化影响 每帧独立高清，无压缩伪影
    体积 视频本身很小，转 GIF 后暴涨 APNG 偏大，GIF 适中
    可控性 需要重拍或重剪 改一句提示词即可换表演

    一句话：视频转 GIF 是"记录已经发生的运动"，本项目是"在两个状态之间插值"。 前者适合真实动作，后者适合表情包式的微表演，而且可复现、可参数化。

    3 · APNG 的特点（什么时候该用它）¶

    特点 说明
    向后兼容 不支持的软件显示第一帧，不会裂图
    24 位真彩 + alpha 渐变、发丝、半透明光效都能保住
    无损 DEFLATE 压缩，没有色带
    浏览器支持 97.39% Chrome / Edge / Firefox / Safari / Android 全绿（caniuse，2026-11-23）
    桌面查看器支持不一 Windows 自带照片不播 APNG；BandiView、浏览器可以
    体积偏大 每帧整帧 PNG，512² × 24 帧通常 4–7 MB
    无音频 纯图像序列

    适合：网页 / 文档 / Discord（保留 alpha）、本地高清回看、需要"静态图兜底"的场景。

    4 · APNG 转 GIF 会发生什么¶

    APNG → GIF 不是换壳，是降维编码。四件事一定发生：

    4.1 颜色：24 位 → 8 位调色板¶

    GIF 每帧最多 256 色。两种做法：

    做法 结果
    逐帧各自量化 帧与帧之间调色板跳变，播放时颜色"呼吸"、闪烁
    全片统一调色板 不闪，但整片只能用 256 色，渐变与肤色容易出色带

    本项目的 GIF 走 VHS 的 image/gif：palettegen 一次 + paletteuse 统一套用， 抖动算法 sierra2_4a。所以不闪，但色带和抖动噪点是必然的。

    4.2 透明：真 alpha → 1-bit 透明¶

    APNG 的半透明（比如发梢、光晕）在 GIF 里只能全透明或全不透明， 边缘会出现硬边或白边。要透明素材，优先 WebP 或 APNG。

    4.3 时间：毫秒级 → 1/100 秒¶

    GIF 的帧延迟单位是 1/100 秒（GIF89a 的 GCE），所以实际帧率只能落在 100/n：

    目标 fps GIF 实际延迟 实际 fps
    10 10cs 10.00
    12 8cs 12.50
    9 11cs 9.09
    8 12cs 8.33

    另外多数浏览器对过短延迟有下限钳制，所以做表情包 8–12fps 就够，再高既看不出来也不准。

    4.4 体积：不一定变大¶

    直觉上 GIF 更差所以更大，实际常常相反——因为 GIF 的 LZW + 256 色对平涂动漫非常友好。 本项目实测（512² × 24 帧）：

    环境 APNG GIF WebP（lossless）
    SDXL 6.61 MB 2.41 MB 0.80 MB
    Moss 4.15 MB 2.72 MB 2.88 MB

    结论：GIF 通常比无损 APNG 小，但 WebP 开 lossless 时不一定比 GIF 小；要小就关掉 lossless、quality 80–90。

    4.5 还有两个细节¶

    • 相同帧会被合并：Pillow 写 APNG 时，像素完全相同的相邻帧会被丢弃并把 duration 累加到上一帧； GIF 侧不同编码器行为不一致，所以同一对 latent 上的比例不能重复（不同段之间同值是安全的）。
    • 循环次数：APNG num_plays=0、GIF 的 NETSCAPE2.0 扩展 loop=0，都是无限循环，语义一致。

    4.6 网页预览：为什么最终用 WebP¶

    仓库里的 docs/assets/preview.webp 是主预览，preview.gif 只做兼容备份。

    文件 尺寸 体积 相邻帧差（avg）
    旧 GIF（VHS 直出，512，sierra2_4a） 512×512 3.45 MB 2.49
    新 GIF（全局调色板 + dither=none，384） 384×384 0.76 MB 1.03
    新 WebP（quality 90，384） 384×384 0.57 MB 1.07

    GIF 只有 256 色。VHS 默认用 palettegen + paletteuse，抖动算法 sierra2_4a： 每一帧单独量化，调色板随帧变化，误差扩散的颗粒也在变。播放时人眼看到的就是「色块在闪」， 它和画面本身有没有动是两件事。

    scripts/make_preview.py 的做法：

    1. 所有帧共用首帧的 256 色调色板；
    2. dither=Image.NONE，不做误差扩散；
    3. 缩到 384×384，颗粒更细、体积更小。

    单帧量化误差均值仍在 2.3/255 左右，但帧与帧之间的量化噪声变一致，所以不再有闪烁感。

    7 · 色块闪动的两个来源¶

    排查顺序：先看 APNG，再看 GIF。

    来源 怎么认 怎么修
    生成端：关键帧 denoise 过高 APNG 相邻帧 diff 平均 > 2，脸上/衣服出现补丁状色斑 关键帧 denoise 降到 0.35–0.40；同 seed；同首帧 latent
    生成端：曲线不均 diff 序列中段突然出现 4–5 的尖峰 --curve linear；别用 snap
    编码端：GIF 调色板逐帧变化 APNG 干净，GIF 播放有块状噪点 固定全局调色板 + 关抖动；或改用 WebP
    循环边界 最后一帧到第一帧 diff 特别大 让末拍回到首拍姿势

    实测同一套内容：denoise 0.55 时 APNG diff 2.34、drift 8+；降到 0.35 后 diff 1.08、drift 2.63。 GIF 重编码后再降约 0.05。

    想看这条路线和 Live2D、逐帧 AI、视频生成的定位差异与算力账，见 动图合成方案对比。

    5 · 选型建议¶

    场景 用哪个 理由
    微信 / QQ 聊天、自定义表情 GIF 兼容性最好，体积可控
    网页、Discord、需要透明 WebP 体积小、支持 alpha
    文档、需要"静态兜底"、无损 APNG 不支持时显示第一帧，不裂图
    需要真实动作（走位、转身） 视频模型 → MP4/WebM 本条路线做不了
